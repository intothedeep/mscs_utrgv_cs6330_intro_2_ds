### ISSUE A (blocking, implementation): fabricated intermediate in `ex:hw2-powerlaw-mle`, l.92-95

```
&= 2114.4   && \text{코드로 합산한 값}
\hat\alpha &= 1 + 3409/2114.4
           &= 1.612
```
The code sums to **5569.43**, not 2114.4. And the lines contradict each other:
1 + 3409/2114.4 = 1 + 1.612 = **2.612**, not 1.612. The number 2114.4 = 3409/1.612 was
back-solved from alpha (n/alpha instead of n/(alpha-1)). The comment "코드로 합산한 값" is
therefore false, and so is the aside's claim on l.9 that every number was re-run. Fix:
`5569.4`, then `1 + 3409/5569.4`, then `1 + 0.612`, then `1.612`.
Route: sonnet-writer.

### ISSUE B (blocking, reasoning): n-1 sigma called MLE, l.37, l.44, l.48-52

l.37 and l.44 say all four models use MLE; l.49-50 says "정규분포의 MLE는 표본평균과 표본표준편차
... n-1로 나눈". The MLE of sigma divides by **n**. The n-1 (Bessel) version is the unbiased-variance
estimator, **not** the MLE. The code (`fit_normal` docstring) and the source report say only
"sample standard deviation (n-1)" and never call it MLE, so the chapter added the error. Numerically
immaterial (53.506 vs 53.498), but the claim is wrong. Suggested text: "mu는 MLE(표본평균)이고,
sigma는 MLE(n으로 나눔) 대신 n-1로 나눈 표본표준편차를 썼다. n=3409, 4392에서는 차이가 소수 셋째
자리 이하다." and soften l.37/l.44 to "세 분포는 MLE, 정규의 sigma만 Bessel 보정".
Route: data-analyst to confirm wording, then sonnet-writer (text supplied above).

### ISSUE C (reasoning, should fix): CLT explanation, l.291-293

"평점 하나하나는 여러 개별 투표의 평균이므로 ... 평균은 정규분포에 가까워진다." The CLT describes the

states it as the explanation. Either drop it or reword as a hypothesis ("개별 투표의 잡음은 평균에서

### ISSUE D (reasoning, should fix): "정규가 최악인 이유", l.375-376

Normal is not worst in either table: airport D = 0.358 is 2nd best (it beats exponential 0.379);
movie worst is exponential. Probably meant "지는 이유". Better still, this is the chapter's best
KS-reading example and it goes unused. Normal beats exponential on D for airports even though it
puts 36% of its mass below zero, so a smaller D does not mean a structurally valid model. That
